# Расширение `OzenSync` — метаданные

Расширение конфигурации для **1С:Фитнес клуб** (платформа 8.3.18+, режим блокировок — управляемый,
режим совместимости расширения — не ниже 8.3.18). Префикс имён объектов расширения: `ozs_`.

> Почему не `.cfe` в репозитории: `.cfe` — бинарный артефакт, который собирается в Конфигураторе
> под конкретную редакцию основной конфигурации. В репозитории хранится исходный код модулей
> (`src/**/Module.bsl`) и это описание; ниже — пошаговая сборка за ~15 минут.

## 1. Свойства расширения

| Свойство | Значение |
|---|---|
| Имя | `OzenSync` |
| Синоним | Ozen-Sync: обмен с бухгалтерией |
| Назначение | Дополнение |
| Префикс | `ozs_` |
| Безопасный режим | **Нет** (нужен `HTTPСоединение`) — или профиль безопасности с разрешением на хост бухгалтерии |
| Защита от опасных действий | Нет |

## 2. Перечисление `ozs_СтатусыОбмена`

| Значение | Смысл |
|---|---|
| `Ожидает` | Сообщение в очереди. В том числе — после неудачной попытки, ждёт `ДатаСледующейПопытки`. |
| `Отправлено` | Принимающая сторона ответила 2xx. Финальный статус. |
| `Ошибка` | Dead letter: пакет отвергнут как некорректный (400/422) или исчерпан лимит HTTP-повторов. Требует разбора человеком, возвращается в очередь `ПереотправитьОшибочные()`. |

## 3. Регистр сведений `ozs_ОчередьОбменаСБухгалтерией`

Синоним: «Очередь обмена с бухгалтерией». **Независимый, непериодический**, режим записи — независимый.
Почему не «по регистратору»: у сообщения своя жизнь (статус, попытки) после записи документа, его меняет
фоновое задание, а не перепроведение. Почему не периодический: ключ — идентификатор сообщения, время
хранится в реквизитах.

| Вид | Имя | Тип | Индекс | Назначение |
|---|---|---|---|---|
| Измерение | `Идентификатор` | УникальныйИдентификатор | основной ключ | ID сообщения = `Idempotency-Key` |
| Ресурс | `ТелоJSON` | Строка (неогр.) | — | Тело запроса, снимок документа |
| Ресурс | `КоличествоПопыток` | Число (5, 0) | — | Сколько раз пытались отправить |
| Ресурс | `ТекстОшибки` | Строка (неогр.) | — | Последняя ошибка (сеть / код + тело ответа) |
| Ресурс | `КодОтвета` | Число (3, 0) | — | HTTP-код последнего ответа (0 — ответа не было) |
| Реквизит | `ТипОбъекта` | Строка (50) | — | `ПродажаАбонемента` / `Возврат` / `Оплата` |
| Реквизит | `Операция` | Строка (10) | — | `upsert` / `cancel` |
| Реквизит | `ОбъектСсылка` | ДокументСсылка (составной: документы-источники) | Индексировать | Какой документ породил сообщение |
| Реквизит | `Версия` | Число (15, 0) | — | Монотонная версия снимка, мс UTC |
| Реквизит | `Статус` | ПеречислениеСсылка.ozs_СтатусыОбмена | Индексировать с доп. упорядочиванием | Выборка очереди |
| Реквизит | `ДатаСоздания` | Дата (дата и время) | — | Когда сообщение поставлено в очередь |
| Реквизит | `ДатаСледующейПопытки` | Дата (дата и время) | Индексировать | Экспоненциальный бэкофф |
| Реквизит | `ДатаПоследнейПопытки` | Дата (дата и время) | — | Мониторинг |
| Реквизит | `ДатаОтправки` | Дата (дата и время) | Индексировать | Очистка старых отправленных |

Права: роль `ozs_АдминистраторОбмена` — полные права на регистр; остальным пользователям права **не нужны**:
подписка пишет в регистр в привилегированном режиме.

Формы: достаточно автоформы списка. Рекомендуемые колонки: `ДатаСоздания, ТипОбъекта, Операция,
ОбъектСсылка, Статус, КоличествоПопыток, ДатаСледующейПопытки, КодОтвета, ТекстОшибки`.

## 5. Подписка на событие `ozs_ПоставитьВОчередьОбменаПриЗаписи`

| Свойство | Значение |
|---|---|
| Источник | `ДокументОбъект.РеализацияТоваровУслуг`, `ДокументОбъект.ВозвратТоваровОтПокупателя`, `ДокументОбъект.ПриходныйКассовыйОрдер` (сверьте с `ПравилаВыгрузки()`) |
| Событие | `ПриЗаписи` |
| Обработчик | `ozs_ОчередьОбмена.ПоставитьВОчередьПриЗаписи` |

Именно `ПриЗаписи`, а не `ОбработкаПроведения` и не `ПослеЗаписи` на клиенте: обработчик выполняется
в той же транзакции, что и запись документа, — это и есть Transactional Outbox.

## 6. Регламентные задания

| Имя | Метод | Расписание | Предопределённое | Повторы при аварии |
|---|---|---|---|---|
| `ozs_ОтправкаОчередиВБухгалтерию` | `ozs_ОтправкаВБухгалтерию.ОтправитьОчередьРегламентноеЗадание` | каждые 60 сек | ✔, Использование = Истина | 3 раза через 10 сек |
| `ozs_ОчисткаОчередиОбмена` | `ozs_ОтправкаВБухгалтерию.ОчиститьОтправленныеРегламентноеЗадание` | ежедневно 03:00 | ✔, Использование = Истина | — |

## 7. Сборка `.cfe`

1. Конфигуратор → *Конфигурация → Расширения конфигурации → Добавить*, заполнить свойства из п. 1.
2. Создать перечисление (п. 2), регистр (п. 3), роль `ozs_АдминистраторОбмена`.
3. Создать три общих модуля (п. 4) и вставить код из `src/CommonModules/*/Module.bsl`.
4. Создать подписку (п. 5) и регламентные задания (п. 6).
5. *Конфигурация → Проверка конфигурации* (расширенная проверка, флаг «Сервер»). Ошибок быть не должно.
6. *Обновить конфигурацию базы данных (F7)*, затем *Конфигурация → Сохранить конфигурацию в файл…* → `OzenSync.cfe`.

Зависимость от БСП: используется только `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
(есть в 1С:Фитнес клуб). Для конфигурации без БСП эту строку можно удалить.
